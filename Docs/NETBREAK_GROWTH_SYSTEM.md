# NETBREAK — Run Growth System Design

> 문서 상태: 성장 구조 확정안 / 개별 수치·콘텐츠는 단계별 검증 전 임시값  
> 적용 범위: 정식 Normal Run 해역 1~6을 전제로 설계하되 실제 Vertical Slice 콘텐츠는 해역 1만 구현  
> 플레이어 노출 문구: 한국어 / 코드 식별자: 영어  
> 구현 상태는 반드시 `NETBREAK_STATE.md`를 확인한다. 이 문서는 이미 구현되었다는 뜻이 아니다.

## 0. 이 문서의 사용법

- **확정 규칙**은 구현 단계가 달라져도 유지한다. 변경할 때는 먼저 사용자와 재논의하고 이 문서를 수정한다.
- **VS 임시값**은 해역 1 플레이테스트를 위한 출발점이다. 반복 튜닝 대상은 기존 authoritative Inspector 필드 또는 해당 Definition 데이터에서 조절한다.
- **향후 제안 / 미정**은 구현 지시가 아니다. 해당 단계 시작 전에 구체화한다.
- 설계 변경을 Codex 프롬프트에만 넣지 않는다. 장기 규칙은 이 문서에 남기고, 실제 완료 상태만 `NETBREAK_STATE.md`에 남긴다.
- 기존 게임의 동작은 각 G 단계가 명시적으로 전환하기 전까지 유지한다. 구 시스템과 신 시스템의 보상은 동시에 중복 지급하지 않는다.

## 1. 핵심 경험과 장기 런 구조

**핵심 판타지: 일반 어부 → 판타지 어부 → 전설적인 어부.** 처음에는 단순한 조업 도구를 쓰다가 Tree·액티브·속성 아이템을 통해 눈에 보이게 강해진다. 같은 해역 1에서 매번 시작하더라도 장비 선택, 포인트 투자, 아이템 등장으로 다른 빌드가 만들어져야 한다. 후반에는 일반 어군의 반복 처리 부담을 낮춰도 좋지만 특수어와 보스에는 여전히 판단이 필요하다.

Normal Mode는 모든 Run을 해역 1에서 시작한다. 진행 해금에 따라 한 Run에서 해역 1, 이후 1→2, …, 최종적으로 1→2→3→4→5→6을 순서대로 진행한다. 새로 개방한 마지막 해역의 보스를 잡으면 해당 Run을 마치고 다음 해역이 해금되는 기존 원칙을 유지한다.

해역 전환 시 **유지:** 현재 레벨·EXP, 미사용/사용한 숙련 포인트, Core/Partner, 두 Tree의 투자 상태, E/R 해금과 장착, 아이템·아이템 레벨·속성 합계, 골드 및 기타 Run 빌드 상태. **초기화:** 실제 맵에 배치한 낚싯대·그물·미끼 등의 오브젝트와 위치, 어군·보스, 해역 한정 상태. Run과 영구 Meta Progression은 별개이다.

한 Run은 조업 시작부터 결과 화면까지이며 해역 이동은 새 Run 시작이 아니다. 고정 목표 플레이타임이나 절대 상한은 두지 않는다. 30분 이내 종료를 요구하지 않고 1시간 이상 진행되는 Run도 허용하지만, 특정 시간을 채우려고 반복·대기·적 Resistance를 억지로 늘리지 않는다. 해역별 시간과 전체 Run 시간을 분리해 측정하며 성장 밀도, 전투 변화, 전략적 판단과 지루함 여부를 우선 평가한다. Area 1만 있는 Vertical Slice가 일찍 끝나는 것은 정상이고, 해역이 추가되면 전체 Run 시간은 자연스럽게 변한다.

해역 6은 **Normal Mode의 끝이지 게임 전체의 끝이 아니다.** 해역 6 완주 이후 Hard Mode, 플레이어 불이익과 물고기 이점, 별도 메타 재화가 장기 방향이다. Hard Mode 이후의 추가 판타지 해역(예: 용암·지옥·우주)은 확장 아이디어이며 콘텐츠·진행 순서는 아직 미확정이다. VS에서는 구현하지 않는다.

## 2. Vertical Slice 계약과 개발용 미래 상태 테스트

- 실제 플레이 콘텐츠와 보상 규칙은 **정식 해역 1과 동일**하게 만든다. VS 편의를 위해 해역 1에서 아이템 4칸을 주거나 R을 미리 쓰게 만들지 않는다.
- 해역 2~6의 실제 적·맵·경제·레벨 목표는 지금 만들거나 임의로 확정하지 않는다. Run 데이터만 해역 간 지속 가능한 형태로 둔다.
- 정상적인 해역 1 플레이에는 **아이템이 등장하지 않는다.** 해역 1의 마지막 보상으로 R을 얻지만, 다음 해역이 없는 VS 정상 런에서는 실전 사용할 기회가 없다.
- 향후 기능은 Editor/Development Build 전용 테스트 상태로 별도 검증한다. 예: Core/Partner 강제 지정, 숙련 포인트 지급, E/R 강제 해금, 아이템 사전 장착, 랭크 지정, 아이템 보상 강제 호출, 해역/관문 진행 상태 지정. 기본 Off, 출시 빌드 비노출, 일반 보상 흐름과 분리한다.
- **G1에서 전체 Debug UI나 모든 Override를 구현하지 않는다.** 필요한 테스트 주입 경계만 고려하고 기능별 단계에서 최소한 추가한다. 현재 F1/F2/F3 테스트 배속은 유지한다.

## 3. 입력과 도구의 역할

| 입력 | 역할 | 정상 해금 |
|---|---|---|
| LMB | 기본 뜰채. Core/Partner 슬롯 미점유; 현재 Hold 반복 유지 | Run 시작 |
| Q | Core Tool: 런의 주력 포획 수단 | Lv2에서 Tree의 `?` 구매 |
| W | Partner Tool: 보조·제어 또는 두 번째 포획 수단 | Lv3에서 Tree의 `?` 구매 |
| E | 세 번째 일반 도구가 아닌 전술 액티브, 장착형 | 해역 1 첫 MiniBoss 포획 |
| R | Core에 종속된 시각적으로 강한 액티브 Signature | 해역 1 첫 Boss 포획, 해역 2부터 정상 사용 |

VS Core 초기 후보: **Fishing Rod / Net / Cast Net**. Bait는 Core에서 제외한다. Partner 후보: Bait 및 선택한 Core와 다른 Fishing Rod / Net / Cast Net. 두 슬롯에는 **동일 Tool을 중복 장착할 수 없다.** Partner는 지원 전용이 아니라 두 번째 도구를 뜻한다. 추후 도구마다 Core 가능·Partner 가능 여부를 달리 지정할 수 있어야 하지만 별도 중복 Tool enum을 만들지 않는다.

같은 도구가 Core로 선택되었을 때와 Partner로 선택되었을 때에는 **한 Run에서 각각 왼쪽/오른쪽의 독립적인 Tree 인스턴스**로 표시·관리한다. 도구별 정적 정의의 재사용 여부는 구현 판단 사항이다. 이 구분은 같은 도구를 한 Run에서 두 번 선택할 수 있다는 뜻이 아니다.

장기적으로 Core 단독 몰빵과 Core/Partner 균형 투자가 모두 허용된다. 역할 분류 자체가 두 도구의 화력이 동등하다는 약속은 아니다. 특히 투망 Core가 실제로 런을 굴릴 수 있는지는 해당 Tree의 충전·환급 등 성장 설계 후 별도 검증한다.

## 4. 레벨업, 도구 획득, 숙련 포인트

**확정:** 시작 Lv1, 미사용 숙련 포인트 0. 레벨업할 때마다 공용 숙련 포인트 **기본 +1**. Lv2와 Lv3에서도 예외 없이 받는다. 양쪽 Tree는 하나의 포인트 잔액을 공유한다. 사용하지 않은 포인트는 누적되고 해역 이동 시 유지한다. Core/Partner 전용 재화는 만들지 않는다.

| 시점 | 즉시 발생하는 성장 |
|---|---|
| Lv2 | 포인트 +1 → Tree 창에서 왼쪽 Core `?`를 1P로 구매 → 적합한 도구 3택1 → Q 배정 |
| Lv3 | 포인트 +1 → 오른쪽 Partner `?`를 1P로 구매 → 이미 보유한 Core 제외 도구 3택1 → W 배정 |
| Lv4+ | 포인트 +1 → Core/Partner Tree의 노드에 자유 투자 |

Lv2에서 포인트를 받았는데 못 쓰는 상황은 만들지 않는다. Lv2·Lv3의 도구 선택은 **Tree 루트 해금에 포인트를 지출하는 행위**다. Tree를 여는 즉시 게임을 일시정지하고 선택 화면도 일시정지 상태에서 처리한다. 해당 시점의 신규 `?`는 가장 먼저 강조하되, 잔액·레벨·해금 조건 검사는 실제 런 상태에서 수행한다. 루트 구매 후 도구 선택이 취소되거나 실패한 경우 포인트만 사라지는 반쪽 상태가 없어야 한다(획득 절차를 하나의 완료 가능한 선택으로 취급).

Lv4부터는 매 레벨 강제 팝업을 띄우지 않는다. `레벨 업! / 숙련 포인트 +1` 알림과 Tree 열기 수단을 제공한다. 플레이어가 원할 때 Tree를 열어 일시정지 후 투자한다. Lv2·Lv3의 첫 도구 획득 UX는 G2에서 기존 선택 UI를 임시 재사용할 수 있으나, 최종적인 좌우 Tree 안의 `?` 구매·연출은 G3에서 완성한다. **임시 UI는 정식 보상 규칙을 바꾸지 않는다.**

**VS 임시 예산:** 기존 해역 1 풀런 관찰상 Lv9 전후라면 레벨업으로 총 8P, Core·Partner 루트에 각 1P 사용 후 일반 노드용 약 6P가 남는다. 여기에 해역 1 MiniBoss +1P와 Boss +2P가 추가된다. 이는 목표치가 아닌 첫 테스트 기준이다. 이후 해역의 레벨·EXP·숙련 포인트 총량은 아직 미정이다. 레벨당 지급량(기본 1)과 관문별 보상량(기본 MiniBoss 1, Boss 2)은 각각의 authoritative 설정에서 조절한다. 관문 포인트는 Run 전용이며 Meta 재화로 전환하지 않는다.

## 5. 스킬 트리: 투자, 랭크, 제한, UI

한 Tree 창에서 **왼쪽 Core / 오른쪽 Partner**를 동시에 볼 수 있다. 미선택 슬롯은 `?` 루트로 표시한다. 확대·축소 및 드래그 이동은 장기 UX 목표이나 G1에서 UI를 만들지 않으며, G3에서 VS에 필요한 범위만 구현한다. 플레이어에게는 노드명·현재 랭크·다음 랭크 효과·비용·잠금 이유를 한국어로 표시한다.

도구가 결정되면 해당 Tree의 **전체 노드 구조와 향후 랭크를 볼 수 있다.** 전체 노드를 숨기는 대신 각 노드의 현재 구매 가능 랭크에 제한을 둔다. 자유로운 분기 투자와 Core 몰빵은 허용하되, 다음 랭크 비용·노드별 상한·선행 조건·해금 관문으로 너무 빠른 완성을 방지한다. Core와 Partner에 강제로 1:1 투자하게 만들지 않는다.

- 각 노드는 안정적인 식별자, 소속 도구, 한국어 표시 데이터, 선행 조건, 현재 Rank 및 Max Rank, **다음 Rank별 비용**, 효과 수치와 랭크별 해금 조건을 표현할 수 있어야 한다.
- VS 초기 Rank 비용 예: Rank1=1P, Rank2=2P, Rank3=3P. **개별 노드·랭크마다 설정 가능**하며 하드코딩된 단일 공식만 허용하지 않는다.
- **Max Rank와 현재 Run의 허용 Rank Cap은 다르다.** 예를 들어 장기 MaxRank 5여도 해역 1에서는 1~2까지만 구매 가능하다. 현재 투자 랭크는 해역 전환 시 초기화하지 않는다.
- Node 간 선행 조건 및 Player Level·해역 진행·MiniBoss/Boss 완료 상태를 필요할 때 조합한다. 모든 노드에 기계적으로 `해역 1=1랭크, 해역 2=2랭크`를 강제하지 않는다.
- 노드 효과를 적용할 때 중복 적용하거나 한 Run에만 존재해야 하는 데이터를 Definition에 저장하지 않는다. 포인트 부족, Rank 초과, 선행 조건 미충족이면 지출하지 않는다.
- 기본 VS는 작게 시작한다. 도구별 5~7개의 Core 관련 노드 / 4~6개의 Partner 관련 노드 정도는 **콘텐츠 제안**일 뿐 실제 노드 구성·효과는 G3 세부기획에서 확정한다. 모든 장기 랭크를 해역 1에서 구매하도록 하지 않는다.

**현재 Random Augment와 Job의 미래:** 기존 도구 증강은 Tree 노드로, 전체 빌드 시너지는 필요하면 아이템으로 이전한다. 기존 Angler/Job 수치 중 유효한 것은 Tool Tree의 노드/분기로 흡수한다. 새 Tree와 구 레벨업 Augment·Job을 최종적으로 동시에 운영하지 않는다. 그러나 G1에서는 기존 시스템을 삭제하거나 전환하지 않는다. 마이그레이션 시점을 명시한 뒤 단계적으로 바꾼다.

### G2+G3 Vertical Slice 확정 콘텐츠

- Lv2 Core와 Lv3 Partner는 최종 양면 Tree 화면 안에서 처리하며, 각 `?` 루트 구매 비용은 기본 1P다. 필수 획득 중에는 닫기·Escape·Tab으로 이탈할 수 없고 확정 뒤에는 일반 Tree 탐색 상태가 되어 자유롭게 닫을 수 있다.
- Tree는 기본 `Tab` 또는 HUD Button으로 열며 열려 있는 동안 일시정지한다. 좌우 콘텐츠는 각자의 `RectTransform`을 드래그하고 휠로 확대·축소한다. 확대 범위·감도는 `SkillTreePanZoom`에서 조절한다.
- 현재 VS 기본 트리는 도구별 2개 노드로 작게 시작한다. 주 노드는 3랭크(비용 1/2/3), 보조 노드는 주 노드 1랭크를 요구한다. 주 노드 3랭크는 해역 2 도달 조건을 표시해 장기 Max Rank와 현재 허용 Rank Cap의 차이를 검증하지만 해역 2 콘텐츠를 구현하지 않는다.
- 낚싯대: 포획력 다중 랭크 + 선행 포획력 뒤 범위. 그물: 최대 길이 다중 랭크 + 선행 길이 뒤 설치 상한. 투망: 포획력 다중 랭크 + 선행 포획력 뒤 반경. 미끼: 유인 반경 다중 랭크 + 선행 반경 뒤 지속시간.
- `SkillTreeDefinition` 에셋은 같은 Tool/Role 조합의 내장 VS 기본 정의를 대체할 수 있다. 에셋이 없어도 내장 정의로 기능하며, 에셋을 사용하면 비용·효과·랭크 조건을 데이터로 튜닝한다.
- 기존 Random Augment의 `FishingRodPower/Range`, `NetLength`, `CastNetPower/Radius`, `BaitRadius/Duration`에 대응하는 효과를 Tree로 이전했다. 레벨업 Random Augment 호출은 중단한다. Landing Net 계열, Cast Net Cooldown/Full Haul, Fishing Rod Speed/Extra Hook은 기존 소스만 남고 현재 레벨 보상에서는 휴면이다. Job은 G4 전 임시 흐름을 유지한다.

### G4-A 관문 포인트와 Legacy Job 효과 전환

- 모든 해역의 MiniBoss 포획 성공은 기본 **숙련 포인트 +1**, 모든 해역 Boss 포획 성공은 기본 **숙련 포인트 +2**를 준다. 해역별·관문별 한 번만 지급하며 실패·도주·타임아웃에는 지급하지 않는다. 새 Run은 이 지급 기록과 포인트 잔액을 새로 시작한다.
- 고급 노드는 MiniBoss 포획 뒤 **구매 가능**해질 뿐 자동 적용되지 않는다. 플레이어가 공용 숙련 포인트를 지출하며 기존 선행 노드·랭크 비용·Rank Cap 검사를 그대로 거친다.
- 낚싯대의 기존 낚시꾼 효과(설치 상한 3→12, 설치 비용 최종 ×0.9)는 설치 상한 3개 랭크와 비용 감소 2개 랭크로 분리했다. 그물잡이의 설치 상한 10은 기존 `여분의 그물` 후속 랭크로 합치고, 비용 최종 ×0.7과 포획력 최종 ×3은 각각 2개 랭크로 분리했다. 투망꾼의 최대 충전 1→3은 2개 랭크로 분리했다. 누적 최종값은 현재 직렬화/기존 구현 값을 보존하는 출발점이며 개별 비용·효과는 `SkillTreeDefinition` 데이터로 조정한다.
- 뜰채잡이의 반경 ×2·대상 최소 8·자동 사용은 Landing Net이 현재 Core/Partner Tree 대상이 아니므로 G4-A에서 Tree로 옮기지 않는다. Random Augment 가중치는 G3 이후 레벨업 Augment가 중단되어 휴면이다.
- G4-B에서 정상 MiniBoss 보상 흐름의 기존 Job 선택과 진행 대기를 E 필수 선택으로 교체했다. Legacy Job 인프라는 다른 참조를 위해 남기지만 정상 gameplay에서는 요청하지 않으며, 구 Job gameplay modifier도 계속 적용하지 않는다.
- 현재 해역 1 노드 대부분을 미래 진행 보존만을 이유로 새로 잠그지 않는다. G4-A는 확인된 Job 효과에 필요한 고급 노드만 추가하며, 장기 Tree 노드·분기·랭크 확장과 전체 포인트 경제 조정은 G4 기능 완료 뒤 별도 마일스톤에서 다룬다.

## 6. E 전술 액티브와 R 궁극기

### E: 첫 MiniBoss의 보상

해역 1 MiniBoss **포획 성공 → 숙련 포인트 기본 +1, E 슬롯 해금 및 E 후보 3택1 무료 선택**. 후보는 정확히 `선택한 Core 도구의 E 1개 + 선택한 Partner 도구의 E 1개 + 범용 E 1개`다. Core와 Partner는 서로 다른 도구이므로 세 선택지는 중복되지 않는다. E 해금·장착에는 숙련 포인트를 소비하지 않으며 리롤은 없다. 필수 선택 중에는 닫기·Escape·Tab·배경 클릭으로 이탈할 수 없고 선택 뒤 기존 개발 배속 x1/x2/x3을 복원한다.

| 연결 | VS E | 동작 |
|---|---|---|
| 낚싯대 | 급속 릴링 | 일정 시간 설치된 낚싯대와 효과 중 새로 설치한 낚싯대의 공격 속도를 높인다. 기본 공격 간격은 덮어쓰지 않는다. |
| 그물 | 긴급 봉쇄 | 기존 규칙이 허용하는 설치 그물을 재가동하고 일정 시간 포획력과 감속을 강화한다. 복어 방해는 계속 유효하다. |
| 투망 | 비상 투망 | 위치 지정 뒤 충전을 소비하지 않는 투망 공격을 1회 사용한다. |
| 미끼 | 과잉 집어 | 일정 시간 활성 미끼의 유효 유인 반경을 확대한다. 기본 미끼 반경은 덮어쓰지 않는다. |
| 범용 | 집중 조업 | 위치 지정 뒤 임시 구역을 만들고, 구역 안 물고기가 기존 포획 도구의 Resistance 피해를 더 받게 한다. |

E는 전술 스킬 전용 입력이다. 즉시형은 E로 바로 발동한다. `비상 투망`은 E를 누르는 동안 조준하고 E를 떼면 현재 위치에 발사하며, `집중 조업`은 E로 조준을 시작해 LMB로 확정한다. 지정 중 RMB 또는 Escape는 취소하며 쿨다운·자원·공격을 소비하지 않고, 비상 투망은 취소 뒤 E를 떼어도 발사하지 않는다. Q/W는 Core/Partner 도구, R은 별도 Signature 슬롯으로 유지한다. 쿨다운과 지속시간은 scaled gameplay time을 사용하므로 선택 UI 등 `timeScale=0` 상태에서는 진행하지 않는다. 새 Run은 E 해금·장착·쿨다운·임시 효과를 초기화한다.

MiniBoss 포획 실패/도주/타임아웃 → 즉시 Run Failure라는 현재 관문 규칙 유지. 해당 어군의 일반 지원 물고기 누락은 MiniBoss 실패로 간주하지 않는다. 큰 어군 자체에는 추가 대형 성장 보상을 강제하지 않는다.

### R: 첫 Boss의 보상

해역 1 Boss 포획 성공 → **숙련 포인트 기본 +2, Core에 맞는 R 슬롯/Signature 해금**. 정상적인 VS에서는 보상 포인트를 기록한 뒤 Run이 종료되므로 마지막 2P를 쓸 수 없는 것이 의도된 동작이다. R 실전 사용은 개발용 미래 상태로 확인하며 정식 진행에서는 해역 2부터 사용한다. G4-C1에서 대표 R 3종의 해금·실행을 구현했다.

- R은 기본적으로 **시각적 사용 순간이 분명한 액티브 궁극기**다. 단순 영구 패시브 수치 증가를 기본형으로 삼지 않는다. 패시브 성격의 후보도 사용 시점과 활성 상태가 시각적으로 뚜렷해야 한다.
- 장기적으로 Core별 **R 후보 N개 중 선택**을 지원한다. VS 콘텐츠는 Core당 대표 R 1개로 시작하며, 후보가 하나일 때 가짜 3택1 화면을 만들지 않는다. 장기적으로 후보가 충분하면 3택1 등의 선택이 가능하도록 한다.
- R의 기본 효과는 Boss 보상으로 무료 해금하고, 이후 Core Tree의 R 강화 노드에 숙련 포인트를 투자해 지속시간·추가 대상·기능 변형 등을 성장시킨다. Partner는 R을 결정하지 않는다. R은 중장기 쿨다운을 가진다.
- E의 VS 콘텐츠와 임시 수치는 G4-B에서 구현했다. R의 VS 콘텐츠와 임시 수치·placeholder visual은 G4-C1 기준을 따른다.

### G4-C Vertical Slice R 확정 콘텐츠

- Boss 포획 등록 시 기존 숙련 +2를 먼저 지급하고, 같은 Run의 Core가 낚싯대/그물/투망이면 해당 대표 R을 자동 해금·장착한다. 첫 Boss에서는 선택 화면을 열지 않는다. `R 스킬 해금: {스킬명}` 공지를 2초간 표시한 뒤 기존 결과 화면으로 진행한다.
- R 상태와 장착 ID는 `RunGrowthState.SignatureR`에 속하며 새 Run에서 초기화된다. E와 R은 쿨다운·대상 지정·지속 효과 상태를 공유하지 않는다.
- 공통 기본 쿨다운은 90초다. 일시정지와 선택 UI 중에는 쿨다운·지속 효과·연속 시전 간격이 진행하지 않는다. Skill Tree, Pause, 선택 모달, 결과/실패 및 기타 입력 차단 상태에서는 사용할 수 없다.
- 실제 효과 영역은 `SignatureSkillManager.gameplayViewport`가 나타내는 Camera pixel viewport 내부 정규화 조업 영역을 사용한다. 기본 `(x 0, y 0.12, width 1, height 0.72)`는 하단 Hotbar와 상단 HUD를 제외한다. 카메라 전체 월드 크기를 무조건 사용하지 않는다.

| Core | R | VS 동작 |
|---|---|---|
| 낚싯대 | 어장 대횡단 | 조업 영역을 기본 9개 가로 Lane으로 나누고 Lane마다 부표 1개를 생성한다. 모든 부표가 우→좌로 동시에 1회 횡단한다. 한 횡단에서 같은 물고기는 최대 1회만 피해를 받고 다음 횡단에서는 다시 피해를 받을 수 있다. 설치 낚싯대가 없어도 독립 실행된다. |
| 그물 | 교차 봉쇄 | 조업 영역을 덮는 실제 충돌 폭의 X자 그물을 기본 6초 생성한다. 접촉 중 일반/복어/오징어는 정지, MiniBoss는 이동 ×0.5, Boss는 ×0.65다. 최대 Resistance 기준 초당 피해는 각각 3%/3%/3%/1.5%/0.75%다. 종료·Run 종료 시 이동 배율을 제거한다. |
| 투망 | 천망 | R을 누르는 동안 조준하고 놓으면 현재 커서에 조업 영역 높이 100% 지름의 투망을 1회 던진다. RMB/Escape 취소 뒤 R을 놓아도 시전·쿨다운·일반 충전을 소비하지 않는다. 후속 시전 수를 늘리면 기본 0.6초 간격마다 그 시점의 커서 위치를 다시 사용한다. |

`SignatureSkillManager`가 R 수치의 authoritative Inspector 소유자다. 어장 대횡단은 Lane 수, 횡단 시간, 부표 판정 반경, 횡단 수, 횡단 간격과 `Normal/Pufferfish/Squid/MiniBoss/Boss`별 고정 Resistance 피해를 노출한다. Area 1의 실제 Resistance 최대값인 일반 25(참치), 복어 18, 오징어 24를 한 횡단 포획 목표값으로 사용한다. MiniBoss 55와 Boss 70은 즉시 포획이 아닌 임시 강한 피해다. 교차 봉쇄는 지속시간, X 팔 두께, 범주별 최대 Resistance DPS 비율과 이동 배율을 노출한다. 천망은 지름 배율, 기존 투망 포획력에 곱하는 피해 배율, 시전 수, 간격, 임시 표시 시간을 노출한다.

개발 검증은 Editor 또는 Development Build의 Play Mode에서 Core를 먼저 선택한 뒤 RunManager의 `SignatureSkillManager` 컴포넌트 Context Menu `Development/Unlock Core Signature R`을 사용한다. 출시 빌드에서는 이 경로가 상태를 변경하지 않는다. Scene에 튜닝값을 저장하려면 `NETBREAK/Growth/Setup Tactical Skill Manager` 메뉴가 기존 RunManager를 보존하면서 E/R 매니저와 기존 Cast Net 참조를 연결한다. 메뉴를 실행하지 않아도 런타임 fallback은 동작한다.

### G4-C2 E/R 강화와 Compact Graph

- Q/W/E/R은 하나의 Run 전용 숙련 포인트 잔액을 공유한다. E/R 자체 해금은 무료이고 강화만 포인트를 소비한다. E는 실제 선택한 스킬의 노드만 보이며 선택 전에는 잠금 사유를 표시한다. R은 선택 Core의 대표 R 그래프를 해금 전부터 잠금 상태로 보여 주며 실제 `RunGrowthState.SignatureR` 해금 뒤에만 구매할 수 있다.
- 모든 E는 서로 독립인 단일 랭크 `효과` 1P와 `재사용` 2P를 가진다. 실제 Inspector 기본값을 기준으로 효과 배율과 쿨다운 배율을 적용한다. 기본값이 현재 VS 값일 때 급속 릴링 ×2→×2.5/24→20초, 긴급 봉쇄 ×1.75→×2/28→24초, 비상 투망 반경 ×1→×1.2/18→15초, 과잉 집어 ×1.75→×2.1/22→18초, 집중 조업 피해 ×1.5→×1.8/26→22초다.
- 낚싯대 R은 `횡단` 2랭크(2P/3P)로 1→2→3회, 그물 R은 독립된 `지속`과 `저항 피해` 2랭크(각 2P/3P)로 Inspector 기본 지속시간 ×1/×1.333/×1.667 및 기본 DPS ×1/×1.33/×1.67, 투망 R은 `연속 투망` 2랭크(2P/3P)로 1→2→3회가 된다. 후속 천망은 기존 0.6초 간격과 매 시전 시점의 커서 위치를 유지한다.
- `TacticalSkillManager`와 `SignatureSkillManager`의 직렬화 값이 기본값의 단일 출처다. `SkillTreeDefinition`은 비용·랭크·선행 조건과 상대 조정값만 소유하며 구매 시 Inspector 값을 덮어쓰지 않는다. 발동 시 유효값을 스냅샷하므로 진행 중 쿨다운이나 이미 활성화된 임시 효과는 Tree 구매로 소급 변경되지 않는다.
- Tree UI는 Q/W/E/R 4영역의 작은 노드와 실제 Definition 선행 조건 연결선으로 구성한다. 긴 설명·현재/다음 효과·비용·선행 조건·잠금/포인트 부족/최대 랭크 상태는 마스크 밖 공용 Hover Tooltip에 표시한다. 노드 그래프는 정의 위치 또는 선행 깊이 기반 자동 배치를 사용하고 Pan/Zoom을 유지한다.
- 기존 Scene UI는 `NETBREAK/UI/Migrate Skill Tree UI To Compact Graph`를 사용해 명시적으로 이관한다. 기존 Core/Partner Branch와 획득 선택은 보존하고 E/R Branch와 공용 Tooltip만 추가하며, 부분 구조·중복을 감지하면 변경 전 중단한다. Undo와 재실행을 지원하고 Scene/Prefab YAML을 직접 수정하지 않는다.

## 7. 아이템: 4슬롯, 선택, 랭크, 속성

아이템은 특정 Tool에 부착되지 않는 **독립적인 자동 패시브 전투 시스템**이다. Core/Partner 조합이나 낚싯대·그물·투망·미끼 소유 여부로 후보 자격을 제한하지 않으며 별도의 사용 키를 추가하지 않는다. Tree는 플레이어가 계획하는 성장, 아이템은 Run이 제공하는 랜덤성과 속성 시너지다.

### 선택과 슬롯

- 새 아이템 보상: **기본 랜덤 3택1**. 풀이 커진 정식 버전에서는 5택1 등으로 조정 가능. 제시 수는 하나의 authoritative 데이터 값으로 조절한다.
- 아직 빈 슬롯이 있으면 미보유 아이템의 신규 획득을 우선한다. 한 Run에서 동일한 아이템을 별도 슬롯에 중복 장착하지 않는다.
- **4칸이 모두 차면** 이후 일반 아이템 보상은 업그레이드 모드로 바뀐다. 보유 아이템 **무작위 2택1**, 선택 아이템 **Lv+1**. 업그레이드 선택 수의 기본 규칙은 2개로 유지하되 확장 가능한 구조로 구현한다.
- 후보가 요청 선택지 수보다 적으면 중복·가짜 선택지를 표시하지 않고 실제 적격 후보만 제시한다. 후보가 0이면 보상 처리 방침을 해당 구현 단계에서 명시한다. 상점 구매/교체처럼 일반 보상과 다른 획득 경로의 슬롯·중복 정책도 G5/G7에서 정한다.

G5-A의 최초 카탈로그 6종은 G5-B에서 다음 Lv1 효과로 동작한다. 아래 수치는 `ItemEffectManager` Inspector의 초기값이며 밸런싱 시 해당 컴포넌트만 조절한다.

### 속성과 아이템 레벨

새 아이템은 Lv1로 시작하고 업그레이드마다 정확히 Lv+1 한다. 기본 최대 레벨은 5이며, `ItemEffectManager`의 각 아이템 Header에서 유한 최대 레벨과 명시적인 무제한 옵션을 독립 설정한다. 유한 최대 레벨에 도달한 아이템은 일반 업그레이드 후보가 아니며, 최대값을 현재 레벨보다 낮춰도 이미 획득한 레벨을 삭제하지 않는다. Run별 현재 레벨은 `RunGrowthState.ItemInventory`만 소유하고 Definition/Inspector 기준값은 변경하지 않는다.

G6-A1의 1차 레벨 스케일링은 모두 Lv1 기준에 대한 가산식이다. 폭풍 구슬·축전 코일·자동 검진은 레벨당 기준 Resistance 피해 +20%, 유령 검집은 +25%다. 서리 인장·빙결 결정은 레벨당 둔화 지속시간 +0.4초다. 빙결 결정의 Resistance 피해, 두 얼음 아이템의 둔화율, 모든 발동 주기·적중 횟수·반경·대상 수는 레벨로 변하지 않는다. 각 증가량도 같은 `ItemEffectManager` 아이템 Header에서 조절한다. 이미 끝난 피해와 이미 적용된 둔화는 소급 변경하지 않고 다음 발동부터 새 레벨을 읽는다.

해당 속성을 지닌 **실제 소유 아이템들의 현재 레벨 합 = 속성 레벨**이다. 이 값은 별도 카운터로 저장하지 않고 Inventory에서 요청 시 계산한다. 단일 속성 문턱 기본값은 **2 / 4 / 6 / 8 / 10**이고 효과는 누적된다. Lv2·6·10은 새로운 효과를 여는 주요 단계이고 Lv4·8은 기존 효과의 수치만 강화하는 보조 단계다. `ItemEffectManager > Single-Element Synergy`의 한 `SingleElementSynergyThresholds` 설정이 전기/검/얼음에 공통으로 쓰이며, 실제 소유·현재 레벨을 매 평가 때 조회한다. 단일 속성 시너지는 특정 아이템 ID나 해당 아이템의 원본 공격에 종속되지 않는다. 같은 속성의 현재·미래 아이템은 Catalog의 Element에 따라 자동으로 합산된다. G6-B1은 전기 다섯 단계, G6-B2는 검/얼음 다섯 단계를 구현했다. 조합 시너지는 서로 다른 두 속성이 각각 Lv2 이상일 때만 가능하고, 한 Run에 최대 하나만 활성화하며, 명시적으로 제작한 속성 조합만 존재한다. 조합 시너지가 다른 아이템 효과를 재귀적으로 발동시키지 않는다. G6-C1은 관리 UI와 Run 상태 기반을 준비했고, G6-C2는 세 실제 전투 효과와 정상 플레이 자동 활성·수동 교체를 구현했다.

Item Trigger를 `OnAttackHit`에만 제한하지 않는다. 낚싯대/뜰채의 적중, 그물 접촉·유효 피해, 투망 판정, 미끼의 유인 영향 등 의미 있는 상호작용을 구별한다. 실제 양의 Resistance 피해만 유효한 피해 적중으로 센다. Tool 원천 적중은 조건을 기여할 수 있지만 Item 원천 및 `ItemSynergy` 원천 추가 공격은 다른 Item 조건을 발동하지 않는다. 연속 피해는 같은 원천·대상에 대해 0.5초당 최대 한 번만 적중 카운트하며, 한 범위 공격의 반복 Collider 콜백도 같은 물고기에 중복 카운트하지 않는다. 포획·도주한 물고기는 새 대상에서 제외하고 Pool 재사용 전 물고기별 카운터·임시 상태를 지운다. Item/시너지 원천 포획도 기존 보상을 지급하지만 다른 Item 또는 시너지를 피해 이벤트에서 재귀 발동시키지 않는다.

VS 정상 해역 1은 **아이템 0개**다. 전기·검·얼음 6종은 Area 1 정상 보상에 연결하지 않고 개발 전용 3택 획득으로 검증한다. G5-B 전투 이벤트는 적용된 양의 Resistance 피해만 기록하며 Tool 원천만 아이템 조건에 기여한다. Net과 교차 봉쇄 같은 연속 원천은 동일 물고기·동일 공격 ID·동일 컴포넌트 인스턴스마다 기본 0.5초에 한 번만 아이템 적중으로 센다. 실제 DoT 피해 주기는 바꾸지 않는다. Item 원천 추가 피해는 기존 포획/보상 경로를 사용하지만 다른 아이템 조건을 재귀 발동하지 않는다.

G5-B의 주기 효과는 획득 시 전체 기본 주기에서 시작한다. 대상이 없는 발동은 건너뛰고 다음 정상 주기를 새로 기다리며 공격을 적립하지 않는다. 모든 대상은 Camera의 조업 viewport 안에서 활성·미포획 상태여야 한다. 커서가 없으면 viewport 중앙을 사용한다. 자동 검진의 Resistance 동률과 거리 동률은 Unity instance ID로 결정해 한 실행 안에서 결정적인 순서를 유지한다.

서리 인장과 빙결 결정은 `FishMovement`의 별도 시간제 이동 배율 키로 적용한다. 같은 아이템의 재적용은 지속시간을 갱신하고 무한 중첩하지 않으며, 서로 다른 시간제 둔화 중 가장 강한 값을 사용한다. 이 배율은 기존 Net, 특수어 이동, R 교차 봉쇄 배율과 곱해지므로 Net 정지/둔화를 해제하지 않고 만료 시 다른 제어 상태도 지우지 않는다. None/Pufferfish/Squid/MiniBoss/Boss 모두 같은 40%/30% 감소율을 적용하되 0 이하로 만들지 않는다. 포획·도주·Pool 반환·새 Run·Run 종료에서 카운터와 시간제 상태를 정리한다.

`NETBREAK/UI/Setup Item System UI`는 기존 G5-A UI를 보존하면서 RunManager에 누락된 `ItemEffectManager`를 Undo 지원으로 추가한다. 컴포넌트의 조업 viewport, 연속 적중 간격, 각 아이템 Header의 기준값·최대 레벨·레벨당 증가량, 단일 속성 문턱, 전기/검/얼음 시너지 수치, 시너지 군중제어 감쇠가 유일한 Inspector 튜닝 위치다. G6-A1은 레벨 저장·검증된 업그레이드 API·실제 효과 스케일링·속성 합산, G6-A2는 보유 아이템 2택1 보상 UI, G6-B1은 전기 단일 속성 효과, G6-B2는 검/얼음 단일 속성 효과를 구현했다. G6-C1의 조합 요구 레벨과 변경 쿨다운은 RunManager의 `Combined Synergy / 복합 시너지`에서 조정하고, G6-C2 전투 효과 수치는 `ItemEffectManager > Combined Synergy / 복합 시너지`가 단일 Inspector 소유자로 관리한다.

### G6-A2 아이템 업그레이드 보상

- 업그레이드 보상은 신규 획득과 구분되는 명시적 요청이다. `ItemRewardManager.RequestUpgrade`가 미래 해역 관문용 재사용 진입점이며, 일반 획득 요청을 슬롯이 찼다는 이유만으로 자동 업그레이드로 바꾸지 않는다. 해역 2~3 관문에서 슬롯이 조기에 찬 경우의 명시적 라우팅은 G8 관문 보상 계약에서 연결한다.
- 후보 수는 기존 `ItemRewardManager`의 `Upgrade Candidate Count`에서 조정하며 기본 2개다. 실제 보유 목록만 순회하고 G6-A1 `ItemEffectManager.CanUpgradeItem`으로 자격을 판정한다. 유한 최대 레벨·잘못된 ID·미보유·유효하지 않은 현재 레벨·정수 overflow는 제외하고, 무제한 최대 레벨 아이템은 `int.MaxValue` 전까지 유지한다. 적격 풀을 한 번 섞은 뒤 앞에서 필요한 수만 취하므로 중복이나 무한 반복이 없다.
- 적격 아이템이 2개 이상이면 기본 2택, 1개면 빈 카드 없이 1택이다. 0개면 모달을 열지 않고 `NoEligibleCandidates`와 한국어 개발 진단을 반환한다. 임의 아이템 자동 강화, Gold·숙련 보상 대체는 하지 않는다.
- 보상이 열린 뒤에는 제시된 후보 ID를 해당 보상에 고정한다. 선택 시 대기 상태와 제시 후보를 확인하고 현재 소유·업그레이드 자격을 다시 검증한 뒤 G6-A1 `TryUpgradeItem`을 호출한다. 성공한 경우에만 보상을 소비하고 정확히 한 아이템을 Lv+1 하며, 실패하면 레벨과 보상 대기 상태를 유지한다. 처리 중 잠금과 소비 상태로 더블 클릭·반복 콜백·비제시 아이템·한 보상의 이중 강화를 막는다.
- 기존 Item reward 모달을 재사용한다. 카드에는 한국어 이름·속성·`현재 Lv → 다음 Lv`·Inspector 기준값과 G6-A1 스케일링으로 계산한 실제 주 효과 전후값·`속성 레벨 +1`을 표시한다. Item HUD와 tooltip은 현재 Lv를 표시한다. 속성 HUD는 Inventory 조회값이 1 이상인 속성만 `전기 Lv.N`, `검 Lv.N`, `얼음 Lv.N` 순서로 한 줄씩 표시하며 0인 속성과 별도 활성 시너지 문구는 숨긴다.
- 모달은 필수 선택이며 기존 전체 화면 raycast·`ToolSlotInput` 차단·Skill Tree 외부 모달 정렬을 재사용한다. 다른 Core/Partner/E/결과 모달 또는 타기팅이 이미 진행 중이면 요청을 거절해 겹치지 않는다. 열린 동안 `timeScale=0`을 유지하고 완료 뒤 기존 `ResumeGameplayTimeScale`로 F1/F2/F3 배속을 복원한다.
- 개발 검증은 Editor/Development Build의 진행 중인 Run에서 `ItemRewardManager > Development/Open Item Upgrade Reward`를 실행한다. 이 메뉴도 실제 후보·필수 모달·원자적 업그레이드 경로를 사용하며 아이템을 직접 지급하거나 레벨을 직접 올리지 않는다. UI 보완은 Edit Mode에서 `NETBREAK/UI/Setup Item System UI`를 명시적으로 실행한다. 기존 `ItemSystemUI`, 4슬롯, 툴팁, 획득/업그레이드 카드 3개를 보존하고 `ItemElementLevels`를 HUD 아래 왼쪽으로 이동해 200×84, Top Left, 17pt 다중 행으로 보정한다. 부분/중복/외부 참조는 변경 전에 중단하고 Undo 및 재실행을 지원한다.
- 정상 해역 1에는 계속 아이템 획득·업그레이드가 없다. 해역 2 MiniBoss/Boss와 해역 3 MiniBoss/Boss는 각각 아이템 1~4 신규 획득, 해역 4~6 MiniBoss/Boss는 명시적 업그레이드 보상이며 모든 관문의 기존 숙련 +1/+2는 유지한다. 실제 해역 2~6 gameplay 및 관문 연결은 이번 단계에서 만들지 않는다.

### G6-B1 전기 단일 속성 시너지

- 전기 시너지는 특정 전기 아이템의 공격이 아닌 **유효한 양의 Tool 원천 Resistance 피해**에 반응하는 독립 패시브다. 뜰채, Core/Partner Tool, E, R의 기존 `CombatDamageContext.Tool`을 재사용하고 연속 피해는 기존 source·attack ID·물고기별 0.5초 적중 제한을 함께 사용한다. Item/ItemSynergy 원천은 발동할 수 없고, 같은 Tool 적중은 기존 Item 카운터와 전기 시너지에 각각 독립적으로 기여한다.
- 전기 Lv2 `연쇄 방전`: 기본 쿨다운 7초. Tool 적중 위치를 기준으로 반경 3 안의 적격 물고기 최대 2마리에게 각각 Resistance 10 피해를 준다. 거리→instance ID 순으로 결정하며 중복·비활성·포획·도주·Pool 대상을 제외한다. 트리거 Tool 피해로 이미 포획된 물고기는 대상이 될 수 없다. 임시 번개 visual 기본 0.45초다.
- 전기 Lv4 `전도 확장`: 별도 공격이나 쿨다운을 만들지 않고 연쇄 방전 최대 대상에 기본 +1을 더해 총 3마리로 만든다.
- 전기 Lv6 `감전 방전`: 연쇄 방전으로 실제 피해를 받고 생존한 대상에게 기본 1초의 `electric_synergy.stun` 시간제 정지를 적용한다. 감전 종료 뒤 기본 3초 동안 재감전할 수 없다. Net, Net R, 기존 Item 둔화, 특수어 배율은 별도 modifier로 유지되며 감전 해제는 전용 키만 제거한다.
- 전기 Lv8 `과충전`: 전기 **시너지 피해만** 기본 ×1.25 한다. 연쇄 방전은 10→12.5, Lv10 천둥 폭풍은 18→22.5다. 폭풍 구슬·축전 코일과 다른 Item/Tool 피해 및 Item Level 스케일링은 변경하지 않는다.
- 전기 Lv10 `천둥 폭풍`: 자체 쿨다운 기본 15초가 준비된 뒤 다음 유효 Tool 적중에서 gameplay viewport 안의 적격 물고기 최대 5마리에게 각각 기본 Resistance 18 피해를 준다. 거리→instance ID 순이며 visual 기본 0.65초다. 천둥 폭풍과 연쇄 방전이 동시에 준비됐으면 천둥 폭풍만 발동하고 연쇄 방전 쿨다운도 그 시점부터 다시 7초를 센다.
- 두 쿨다운은 `Time.time`을 사용하므로 Pause에서 정지하고 발동 backlog를 쌓지 않는다. 모든 시너지 피해는 `CombatDamageOrigin.ItemSynergy`로 기존 `FishController.TakeCaptureDamage`와 포획/보상을 재사용하되 Item 카운터·다른 시너지·자기 자신을 재귀 발동하지 않는다.
- 모든 전기 시너지 Resistance 피해는 Normal/Pufferfish/Squid/MiniBoss/Boss에 계산값 100%를 적용하며 보스 피해 배율은 없다. **시너지 추가 군중제어만** `ItemEffectManager > Synergy Crowd Control` 정책을 한 번 적용한다. 기본 MiniBoss ×0.5, Boss ×0.5, 일반/복어/오징어 ×1이며 두 보스 배율은 독립 설정이다. G6-B2의 Ice freeze 지속시간과 Ice 시너지 추가 둔화 강도도 이 정책을 재사용한다.
- 모든 문턱은 `ItemEffectManager > Single-Element Synergy`, 전기 수치는 `ItemEffectManager > Electric Synergy`, 군중제어 감쇠는 `ItemEffectManager > Synergy Crowd Control`이 유일한 Inspector 소유자다. 획득·업그레이드는 Inventory 합계를 즉시 바꾸며 쿨다운·감전/lockout·visual은 포획·도주·Pool 반환·Run 종료·새 Run에서 안전하게 정리된다.
- 속성 HUD는 레벨이 1 이상인 속성만 한 줄씩 유지한다. 각 줄의 TMP link hover는 모든 다섯 단계를 오름차순으로 표시하는 `ElementSynergyTooltip` 하나를 공유한다. 전기/검/얼음의 구현·해금 단계는 `활성`, 미달은 `미해금`이다. 툴팁은 공용 문턱과 각 속성의 실제 Manager 설정값을 읽고 차단 모달 중 숨는다.
- 정상 Area 1 보상은 계속 아이템 0개다. 개발 검증은 `ItemRewardManager > Development/Open Item Acquisition Reward`로 실제 전기 아이템을 소유한 뒤 검증된 업그레이드 메뉴/API를 사용한다. 기본 최대 레벨에서는 폭풍 구슬·축전 코일을 각각 Lv5로 올리면 합계 Lv10이며, 단일 아이템 Lv6 이상 검증은 해당 아이템의 Inspector `Unlimited Maximum Level`을 개발 중에만 켜고 기존 직접 업그레이드 메뉴를 반복 사용한다. Definition이나 정상 경제는 변경하지 않는다.

### G6-B2 검/얼음 단일 속성 시너지

- 검은 기존 연속 피해의 source·attack ID·물고기별 0.5초 인식 제한을 통과한 전역 양의 Tool 원천 적중만 센다. Lv2 `영혼 참격`은 기본 6회마다 트리거 대상이 여전히 적격이면 우선 공격하고, 아니면 적중 위치 반경 기본 3 안의 적격 대상을 거리→instance ID로 고른다. 기본 Resistance 피해 14, visual 0.45초다. 완료된 카운터는 대상이 없어도 소비하며 pending 공격을 적립하지 않는다.
- 검 Lv4 `예리한 영혼`은 필요 적중을 기본 -1해 6→5로 만들고 최소 1회로 제한한다. 업그레이드 전 부분 진행은 보존하되 과거 적중으로 공격을 소급 생성하지 않는다. Lv6 `쌍검 소환`은 원본과 다른 적격 대상에게 기본 Resistance 10의 추가 검을 한 번 소환하고 대상이 없으면 생략한다.
- 검 Lv8 `검기 증폭`은 검 시너지 피해만 ×1.2해 영혼 참격 16.8, 추가 검 12, 검의 비 24로 만든다. Lv10 `검의 비`는 **실제로 원본 검을 공격한** 영혼 참격 3회마다 gameplay viewport의 서로 다른 적격 대상 최대 4마리에게 기본 Resistance 20을 준다. 대상 없는 영혼 참격, 추가 검, 검의 비, Item/다른 시너지는 원본 활성 카운터에 기여하지 않는다. Lv10 해금 전 원본 활성은 검의 비에 소급되지 않는다.
- 얼음은 `FishController.TakeCaptureDamage`가 포획 전 저장한 hit position, `CombatDamageOrigin`, target lifecycle, `CapturedByHit`을 사용한다. **양의 Tool 원천 피해가 실제 포획한 경우만** 처리하고, 같은 instance/lifecycle 중복 결과는 한 번만 인정한다. Item/ItemSynergy 포획·비포획 적중·도주는 발동하지 않는다. 기존 `Capture()`가 보상을 한 번 지급한 뒤 결과를 큐에 넣으므로 얼음 시너지는 포획 보상을 재지급하지 않는다.
- 얼음 Lv2 `냉기 파동`은 포획 위치 반경 2 안의 트리거 물고기를 제외한 적격 대상 최대 2마리를 2초간 25% 둔화하며 visual은 0.5초다. Lv4 `냉기 확산`은 대상 +1로 최대 3마리다. Lv6 `순간 빙결`은 실제 파동 대상에게 기본 1초 빙결을 추가하며 빙결 종료 뒤 4초 lockout이다.
- 얼음 Lv8 `오래가는 한기`는 얼음 시너지 **둔화 지속시간만** +0.5초로 만들어 냉기 파동 2.5초, 서리 폭발 3.5초가 된다. 빙결 지속시간은 늘리지 않는다. Lv10 `서리 폭발`은 Lv10 해금 뒤 Tool 원천 포획 3회마다 그 포획의 냉기 파동을 대체한다. 반경 3, 최대 4마리, Resistance 12, 3초간 30% 둔화, visual 0.7초이며 누적 Lv6 빙결을 같은 대상에 한 번 적용한다.
- `ice_synergy.slow`, `ice_synergy.freeze`, `electric_synergy.stun`, 서리 인장/빙결 결정 키는 각각 독립이다. `FishMovement`는 시간제 modifier 중 가장 강한 감속을 기존 Net·Net R·특수어 배율과 별도로 곱한다. 각 효과 제거는 자기 키만 지우고, 포획·도주·Pool 초기화·새 Run은 런타임 lockout과 modifier를 정리한다.
- MiniBoss/Boss는 검 시너지 및 서리 폭발 Resistance 피해를 100% 받는다. 공용 CC 정책은 얼음 추가 둔화 **강도**와 빙결 지속시간에만 한 번 적용해 기본 MiniBoss/Boss 둔화·빙결 효율을 각각 0.5로 만든다. 기존 Item 둔화·Item Level scaling과 Tool 이동 제어에는 적용하지 않는다.
- Inspector 유일 소유자는 RunManager의 `ItemEffectManager`다. `Sword Synergy`에 6회/14/반경3/0.45초, Lv4 -1, 추가 검 10, Lv8 ×1.2, 검의 비 3회/4대상/20/0.65초가 있다. `Ice Synergy`에 냉기 파동 반경2/2대상/25%/2초/0.5초, Lv4 +1, 빙결1초/lockout4초, Lv8 +0.5초, 서리 폭발 3포획/반경3/4대상/12/30%/3초/0.7초가 있다. 공용 문턱과 보스 CC 배율은 기존 Header를 재사용한다.
- 기존 공유 툴팁은 검/얼음도 다섯 단계를 `활성/미해금`으로 표시하고 실제 Inspector 설정값을 설명에 반영한다. 새 UI 오브젝트나 참조가 없어 G6-B2 때문에 `NETBREAK/UI/Setup Item System UI`를 다시 실행할 필요는 없다. 기존 G6-B1 UI가 없는 Scene만 기존 안전 메뉴를 사용한다.
- 개발 검증은 Editor/Development Build의 실제 Run에서 획득 메뉴로 같은 속성 아이템을 소유하고 검증된 업그레이드 메뉴/API를 사용한다. 기본 최대 레벨에서 두 검 또는 두 얼음 Item을 각각 Lv5로 만들면 속성 Lv10이다. 정상 Area 1 보상은 계속 Item 0개다. G6-C의 명시적 조합 시너지는 한 Run에 최대 하나만 활성화된다.

### G6-C1 성장 관리 아이템 페이지와 복합 시너지 기반

- 기존 Tab `SkillTreeUI/TreePanel` 하나를 성장 관리 창으로 사용한다. 상단은 `[스킬 트리] [아이템]`, 본문은 한 번에 한 페이지만 보인다. 공용 Header/닫기/숙련 표시는 창에 그대로 두고 기존 Q/W/E/R Branch·노드·Tooltip·필수 도구 선택 모달은 같은 크기의 `SkillTreePage` 아래로 감쌀 뿐 다시 만들지 않는다. Run의 첫 페이지는 스킬 트리이고, 사용자가 바꾼 마지막 페이지는 같은 Run에서 닫았다 열어도 유지되며 새 `RunGrowthState`에서 스킬 트리로 초기화된다. Tab 입력 소유자는 계속 `SkillTreeManager` 하나다.
- 아이템 페이지는 실제 `RunGrowthState.ItemInventory`의 4칸을 읽는다. 빈 칸은 그대로 보이고 획득·업그레이드 `Changed`, 페이지 열기·재진입, 새 Run Inventory 재바인딩 때만 갱신한다. 별도 mutable Inventory나 속성 합계는 없다. 아이템 Hover는 `ItemEffectManager.BuildItemTooltipText`를 영구 HUD와 공유해 실제 Inspector 효과값, 현재 레벨, 다음 레벨 개선 또는 최대 레벨을 표시한다.
- 속성 구역은 실제 소유 아이템 합계가 1 이상인 전기/검/얼음만 표시한다. Hover는 기존 `BuildElementSynergyTooltipText`를 재사용해 2/4/6/8/10 다섯 단계, 현재 레벨, `활성/미해금`, Inspector 실제 수치를 보여준다. 아이템·속성 Tooltip은 페이지 전환, 창 닫기, 포인터 이탈, 차단 보상 모달에서 숨고 페이지 경계 안에 보정되며 raycast를 차단하지 않는다.
- 초기 복합 카탈로그 순서는 `뇌검 공명(전기+검) → 초전도(전기+얼음) → 빙검 공명(검+얼음)`이다. G6-C1 당시 각 조합은 두 속성 합계가 기본 Lv2 이상이면 `해금됨 · 구현 예정`, 아니면 `미해금 · 구현 예정`으로 표시했으며, G6-C2에서는 실제 활성 상태에 따라 `현재 사용 중` 또는 `해금됨 · 교체 가능`을 표시한다. 특정 아이템 ID를 요구하거나 레벨·Gold·숙련 포인트를 소비하지 않는다. 세 요구 레벨은 RunManager `Combined Synergy Unlocks`, 수동 변경 쿨다운 기본 30초는 같은 Header의 `Combined Synergy Switch Cooldown`에서 조절한다.
- `RunGrowthState.CombinedSynergy`가 안정 ID, UI 선택 후보, 단일 Active ID, 결정적 카탈로그 순서 자동 선택, 원자적 자격 재검증, 동일 선택 무동작, scaled gameplay time 변경 쿨다운을 소유한다. `RunManager`가 Inventory `Changed`에서 UI와 무관하게 첫 자동 선택 API를 호출한다. 첫 자동 활성은 쿨다운을 시작하지 않고, 이미 Active가 있으면 새 조합 해금이 교체하지 않는다. 이 상태는 같은 Run의 Area 전환에 남고 새 Run에서 선택·Active·쿨다운이 초기화된다.
- **G6-C1 게이트 기록:** G6-C1에서는 세 전투 효과가 없어 `CombinedSynergyCatalog.CombatEffectsImplemented=false`로 정상 자동 활성과 확인 버튼 적용을 거부했다. G6-C2에서 세 효과 연결 후 이 값을 `true`로 전환해 정상 자동 활성과 수동 교체를 개방했으며, 카드는 `현재 사용 중`, `해금됨 · 교체 가능`과 남은 쿨다운을 표시한다.
- G6-C2 전투 규칙은 다음과 같이 구현됐다. 뇌검 공명은 연쇄 방전 8초 표식을 영혼 참격으로 소비해 대상 +18, 주변 최대 2마리 +8, 내부 8초 쿨다운. 초전도는 얼음 시너지 둔화 대상의 연쇄 방전에서 주변 최대 2마리 +8, 둔화 최대 +0.5초, 내부 6초 쿨다운. 빙검 공명은 얼음 둔화/빙결 대상의 영혼 참격에서 주변 최대 2마리 +10, 20% 둔화 1.5초, 내부 6초 쿨다운이다. 반복 튜닝값은 `ItemEffectManager > Combined Synergy / 복합 시너지`에 노출한다.
- 안전 이관 메뉴는 `NETBREAK/UI/Migrate Growth Window To Skill Tree + Item`이다. Edit Mode에서 유일한 기존 `SkillTreeCanvas`와 `ItemHUD`, 완전한 Q/W/E/R·도구 선택 구조를 확인하고, 부분/중복/모호한 구조면 변경 전에 중단한다. Undo와 재실행을 지원하고 영구 `ItemSystemUI`, HUD, 보상 모달을 이동하거나 다시 만들지 않는다. 메뉴 실행과 Main Scene 저장은 사용자 작업이며 별도 수동 Inspector 참조 할당은 없다.

**중요:** 해역 2~3 MiniBoss/Boss의 아이템 획득은 기본 랜덤 3택1이며 후보 수 확장을 지원한다. 나중에 상인·이벤트로 아이템을 일찍 더 얻어 4슬롯이 먼저 찰 수 있지만, 일반 획득 API는 다섯 번째 아이템을 만들거나 요청 타입을 자동 변경하지 않는다. 해역 2~3 관문이 그 상태에서 명시적으로 업그레이드 보상을 요청하는 최종 라우팅 규칙은 G7/G8에서 검증한다. 해역 4~6 MiniBoss/Boss는 처음부터 아이템 업그레이드 요청을 사용한다. 보상 시점 자체를 VS용으로 앞당기지 않으며 해역 1 정상 플레이에는 아이템이 없다.

첫 MiniBoss/Boss는 숙련 포인트와 E/R에 집중한다. 후속 MiniBoss/Boss의 노멀/희귀/전설 등장 확률, 보상 업그레이드량, 상점 등장 시점은 별도 데이터 튜닝 대상이다. **해역 2~6 최종 레벨과 포인트 총량을 지금 임의로 확정하지 않는다.**

### 해역 1 골드 경제에 관한 유의점

해역 1에는 아이템과 상인이 기본적으로 등장하지 않으므로 기존 설치 상한 뒤 골드 잉여 문제가 자동으로 해결되지는 않는다. 이를 숨기려고 상점이나 보상을 VS 전용으로 끼워 넣지 않는다. 새 Core/Partner·Tree 효과를 구현한 뒤 해역 1 경제를 다시 측정하고 필요하면 정식 해역 1에도 남을 경제 수정을 별도 결정한다.

## 9A. 밸런싱 원칙

현재 제한된 도구·아이템·해역을 기준으로 전체 게임의 최종 수치를 확정하지 않는다. 현재 수치는 기능과 구조를 검증하기 위한 임시값이며, 문제가 확인되지 않은 수치를 반복 조정하지 않는다.

**현재 처리할 구조적 밸런스:** 특정 빌드가 다른 선택지를 완전히 무력화하는 문제, 무한 피해 재귀·보상 중복, Gold나 자원의 비정상적 무한 증식, 성장 선택의 의미 상실, 진행 불가능 또는 의도하지 않은 극단적 난이도, 조작 없이 모든 상황을 해결하는 구조적 결함, 실제 플레이에서 확인된 심각한 페이싱 문제다. 현재 버전 Full Run은 이런 기능 안정성과 핵심 경험을 검증한다.

**콘텐츠 확장 이후 처리할 정밀 밸런스:** 아이템별 최종 피해량, 도구별 세부 DPS, 상점 가격·리롤 경제, 희귀도·등장 확률, 전체 해역 난이도 곡선, 최종 Gold 수입·소비 균형, 전체 Run 플레이타임 조정이다. 대표 빌드와 보상 계약이 실제 콘텐츠에 연결된 뒤 중간 밸런스를 거치고, 충분한 콘텐츠가 준비된 후 정밀 조정한다.

G10 Area 1 Balance는 삭제하지 않는다. 목적은 Area 1의 최종 수치 확정이 아니라 정상 보상 조건에서 기본 플레이 가능성, 대표 Core/Partner 빌드 성립, MiniBoss/Boss 진행과 명백한 구조적 문제를 확인하는 것이다.

## 10. 검사 가능한 개발 규칙: Inspector와 단일 출처

**반복적으로 조정할 가능성이 있는 수치는 Inspector 또는 적합한 ScriptableObject Definition에서 조절 가능**하게 한다. 코드 로직·입력 규칙·게임 구조의 불변 조건까지 무차별적으로 필드로 만들지 않는다.

- 노출 전 반드시 같은 수치가 기존 Inspector·FishData·Definition에 있는지 확인한다. **이미 있으면 재사용**, 필드 복제·서로 다른 값의 이중 source of truth·불필요한 이름 변경 금지.
- 기존 Unity의 직렬화된 값과 유저 `.unity`/`.prefab`/`.asset` 변경은 보존한다. C# 초기값으로 기존 Inspector를 재설정하지 않는다. 필드 이동이 꼭 필요하면 데이터 손실 방지 계획부터 제시한다.
- 후보: 레벨당 숙련 포인트(기본 1), MiniBoss/Boss 숙련 보상(기본 1/2), 노드별·랭크별 포인트 비용과 효과량, 해역/레벨별 Rank Cap, E/R 쿨다운·범위·지속시간·효과, 아이템 신규 후보 수(기본 3)·업그레이드 후보 수(기본 2)·확률·랭크별 수치, 속성 문턱·발동 확률, 상점 가격·리롤, 물고기 보상·저항력, Spawn 수치.
- 기존에 Inspector에 있는 EXP `30/80/120`, Lv4+ Base `120`/Growth `1.30`, Starting Gold `0`, 낚싯대 Base Cost `30`, Base Max `3`, 비용 성장 `1.5`, Net Cost `8/6/0.5`, MiniBoss `220`, Boss `700`, Special Warning `4` 등은 **참고용 현 상태 기록**이다. 실제 최신 값은 repo/serialized Unity 상태를 확인해야 하며 이 문서 수치로 덮어쓰지 않는다.
- 구조 규칙인 `Lv2 Core, Lv3 Partner, Q/W 역할, E/R 해금 관문, 아이템 4슬롯 가득 참→업그레이드 전환, MiniBoss 실패=런 실패`는 임의 밸런스 토글로 만들지 않는다. Debug Override는 출시 규칙과 분리한다.
- Inspector 정리는 `[Header]`, `[Tooltip]`, 의미가 명확한 `[Min]` 등을 사용하고 실험을 막는 임의 `[Range]`는 피한다. 실제 데이터 정의를 읽고 필요한 범위만 노출한다.

### G1 상세 범위 잠금 — 완료 당시 계약 기록

G1 완료는 **데이터 기반이 존재하고 기존 게임 동작을 깨지 않았음**을 뜻할 뿐, 새 성장 시스템이 플레이 가능해졌다는 뜻이 아니다.

1. `AGENTS.md`, 이 문서, `NETBREAK_STATE.md` 및 바로 관련된 구현만 읽어 실제 기존 ToolId·RunManager·EXP 소유자·직렬화 구조를 확인한다. 이미 같은 클래스/데이터가 있으면 재사용한다.
2. Core/Partner가 서로 다른 Tool임을 표현할 수 있는 런 상태, 공용 미사용 포인트와 포인트 획득·원자적 지출 API, 선택 도구별 트리 진행도·노드 Rank 조회/갱신 상태를 준비한다. **현재 Lv2/3 보상과 기존 Tool loadout은 G1에서 연결하거나 변경하지 않는다.**
3. 정의와 런 상태를 분리한다. Tree/Node/랭크별 비용·효과·선행조건·현재 허용 Rank를 데이터로 표현하는 최소 범위만 구현한다. ScriptableObject 정의 타입이 적합하면 C# 타입만 준비하고 실제 `.asset`은 추후 콘텐츠 단계에서 만든다. 실제 노드 효과, 임의 샘플 트리 대량 생성은 하지 않는다.
4. E/R은 향후 해금·선택·장착을 기록할 수 있는 최소 상태·식별 경계만 고려한다. 구체적인 스킬 효과나 Input 처리·UI는 G4로 미룬다. Item/Merchant 데이터는 G1에 선구현하지 않는다.
5. Debug는 뒤 단계에서 필요한 미래 상태 설정을 방해하지 않게만 설계한다. 완성형 Override 패널, 치트 커맨드, Scene 편집을 G1에 넣지 않는다.
6. 실질 수치가 추가되면 기존 source of truth부터 확인하고 하나의 Definition/Inspector만 사용한다. 코드·필요한 Markdown만 수정하고, Unity Scene/Prefab/asset 생성·실행, Computer Use, Git commit/push는 사용자가 별도로 요청하지 않는 한 하지 않는다.
7. 새 코드의 의도와 실제 구현 상태를 `NETBREAK_STATE.md`에 기록한다. 장기 규칙 변경이 불가피하면 이 문서도 수정하되, 사용자가 확정한 기획을 조용히 재해석하지 말고 충돌을 보고한다.

**G1 검증:** 소스 수준으로 ToolId 중복/기존 직렬화 영향/현재 레벨업·QWER·Augment·Job 무변경 여부 확인. Unity Compile 및 Play Mode 검증은 사용자가 실시한다. 실행하지 않은 검증을 성공했다고 보고하지 않는다. G2 연결 전까지 새 포인트는 플레이에서 발생하지 않아도 정상이다.

## 13. 파일과 협업의 Source of Truth

- `docs/NETBREAK_GROWTH_SYSTEM.md`: 확정 설계 + 단계별 계약. **구현 완료를 뜻하지 않음.**
- `NETBREAK_STATE.md`: 실제 코드에 구현된 기능, 검증 결과 및 남은 작업.
- `AGENTS.md`: 개발·Git 규칙. 기존 규칙과 충돌 시 임의로 덮어쓰지 말고 사용자에게 알린다.
- 현재 repo의 C#·Unity 직렬화 값은 **실제 동작 및 기존 데이터의 source of truth**. 문서 예시값이 더 오래되었으면 기존 값을 보존하고 차이를 보고한다.

Codex의 기본 역할: 관련 C# 수정·추가·필요한 MD 갱신. 과한 파일 스캔이나 출력, Unity/Computer Use/검증 자동화, prefab/scene/YAML 조작, Git commit/push는 꼭 필요한 경우 사전 협의. 사용자는 Unity Reference 연결·Hierarchy/Prefab 관리·실제 Play 검증·밸런스 Inspector 조정·Commit/Push를 맡는다. Codex 결과를 받은 뒤 어시스턴트가 사용자에게 구체적인 Unity 연결 및 검증 순서를 안내한다.

**역사적 G1 전 운영 기록:** 기존 `Angler Placement Cost Multiplier 0.7 → 0.9` Full Run 밸런스 테스트는 당시 새 성장 구조 구현/검증 전까지 보류했다. 이는 현재 예정 작업이 아니다.
