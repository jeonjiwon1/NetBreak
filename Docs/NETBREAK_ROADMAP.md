# NETBREAK 개발 로드맵 — Vertical Slice에서 상용 1.0까지

기준일: 2026-09-14. 이 문서는 개발 순서와 단계별 검증 목표를 정한다. 출시일, 데모 분량, 미확정 Area 2~6의 세부 게임 설계를 확정하지 않는다. 단계 진입은 앞선 검증 결과에 따라 판단하고, 문제가 발견되면 필요한 이전 단계로 돌아간다.

구현의 기준은 **Git 저장소의 코드와 이력**, 현재 개발 상태의 기준은 **[NETBREAK_STATE.md](../NETBREAK_STATE.md)**다. 본 문서의 예정 항목을 구현 완료로 해석하지 않는다. 게임 설계 원칙은 [NETBREAK_DESIGN.md](NETBREAK_DESIGN.md), 작업 규칙은 [AGENTS.md](../AGENTS.md)를 따른다.

## 전 단계 공통 원칙

- 모든 Run은 Area 1에서 시작한다. 해금된 지역을 선택해 시작하는 체크포인트는 만들지 않는다.
- 지역 해금은 영구 Meta 진행이다. 해금 상한까지 클리어하면 Run 종료 후 다음 지역이 열리며, 다음 Run도 Area 1부터 시작한다.
- Run 빌드는 판 사이에 초기화되지만 같은 Run의 지역 사이에서는 유지된다. 도구/슬롯/증강/직업/Gold/EXP/Level은 유지하고 설치물·활성 미끼·물고기 등 월드 상태는 지역 전환 시 초기화한다.
- Meta 도구 해금과 이번 Run 도구 소유는 별개다. 영구 해금이 현재 Run의 자동 소유를 뜻하지 않는다.
- Secondary Jobs, dual jobs, Final Expertise 및 Area 4~6 시스템을 성급하게 설계 확정하거나 밸런싱하지 않는다. 실제 플레이와 제작에서 확인한 필요에 맞춰 범위를 정한다.
- Area 2는 콘텐츠 제작 파이프라인의 첫 실전 검증이다. Coast 전용 구조의 데이터화는 실제 Area 2 제작이 필요성을 입증할 때 수행한다.
- 외부 플레이테스트로 핵심 루프를 검증한 뒤 Area 2~6의 대규모 제작에 투자한다. 콘텐츠 양으로 핵심 조작이나 재미의 문제를 덮지 않는다.
- 구현은 Git, 현재 상태는 NETBREAK_STATE.md를 기준으로 확인한다. 로드맵과 실제 완료 상태를 분리한다.

## PHASE 1 — Area 1 Vertical Slice

**목표:** Area 1에서 핵심 게임 루프와 빌드 선택을 끝까지 체험할 수 있는 검증용 빌드를 완성한다.

- 현재 게임플레이 구조를 정리하고 동적 도구 로드아웃, 도구 획득, 소유 도구 증강 필터링/시작 지연, 클릭형 Hotbar를 완성한다(STEP 10A~10E).
- 전체 Run을 실측해 경제·페이싱·기존 도구·1차 직업·보스의 첫 본격 밸런스 조정을 진행한다(STEP 11).
- 핵심 VFX/SFX/BGM, 조작 안내와 온보딩을 보강한다(STEP 12~14).
- 회귀 테스트, 배포 가능한 빌드, README 및 포트폴리오 스크린샷/영상을 준비한다(STEP 15~16).

**다음 단계 판단:** Area 1의 시작부터 결과/재시작까지 플레이할 수 있고, 외부 테스트를 막는 주요 결함을 해결했으며 테스트할 빌드와 알려진 문제가 정리되어 있다. 내부 검증만으로 재미가 입증됐다고 간주하지 않는다.

## PHASE 2 — External Playtesting

**목표:** 실제 플레이어가 LURE → TRAP → CATCH를 이해하고 즐기는지 검증한다.

- 개발자의 실시간 설명에 의존하지 않는 플레이를 관찰하고, 이해한 내용과 막힌 지점을 수집한다.
- 조작, 도구를 발견하고 사용법을 이해하는 과정, 빌드 다양성, 페이싱, 경제, 보스 난이도 피드백을 우선한다.
- 반복되는 문제를 먼저 수정하고 수정 빌드로 다시 테스트한다. 의도한 유도·봉쇄·대량 포획이 실제 플레이에서 나타나는지 확인한다.
- 핵심 루프가 외부 테스트를 통과하기 전에는 많은 지역이나 도구를 제작하지 않는다.

**다음 단계 판단:** 핵심 루프의 이해도와 재미를 뒷받침하는 관찰 결과가 있고, 반복적으로 드러난 주요 문제를 해결하거나 검증 가능한 개선 방향을 확보했다. 부족하면 Area 1을 개선하고 재시험한다.

## PHASE 3 — Area 2 / Content Pipeline Validation

**목표:** Area 2를 첫 실제 확장으로 제작해 콘텐츠 추가 방식이 지속 가능한지 검증한다.

- 새 지역, 경로, 물고기, 보스와 인카운터를 추가하는 과정에서 기존 시스템을 얼마나 재사용할 수 있는지 확인한다.
- 실제 제작에서 확인된 반복 작업과 결합 문제를 근거로 Coast 전용 시스템을 필요한 범위만 데이터 기반으로 전환한다.
- 같은 Run에서 Area 1 → Area 2로 넘어갈 때 빌드는 유지되고 월드 상태는 초기화되는지 확인한다.
- Area 2~6 전체의 세부 성장 체계나 보상을 미리 확정하지 않는다.

**다음 단계 판단:** Area 2가 플레이 가능하고, 다음 지역의 경로·어종·보스·인카운터를 추가할 때 주요 구조를 매번 다시 작성하지 않아도 되는 제작 흐름을 확인했다.

## PHASE 4 — Playable / Steam Demo Quality

**목표:** 플레이테스트 결과에 맞는 데모 범위를 정하고 실제 배포 환경에서 신뢰할 수 있는 품질을 확보한다. 데모에 포함할 지역 수와 분량은 여기서 미리 고정하지 않는다.

- 데모 범위에 필요한 저장/Meta 진행을 안정적으로 구현한다.
- 설정, 음량 조절, 화면 옵션, 튜토리얼/온보딩과 빌드 배포 흐름을 마련한다.
- 저장 중 중단이나 충돌 이후에도 진행 데이터가 불필요하게 손상되거나 해금/보상이 중복되지 않도록 저장과 복구를 검증한다.
- 실제 배포 빌드의 설치·실행·플레이·종료·재실행 흐름을 확인한다.

**다음 단계 판단:** 정한 데모 범위가 일관되게 작동하고, 저장/진행·설정·온보딩·배포에서 플레이를 막는 문제가 해결되어 있다. 이 단계의 저장 기반은 PHASE 6에서 전체 Meta 범위로 완성한다.

## PHASE 5 — Full Production

**목표:** 검증된 제작 흐름으로 Area 3~6을 반복적으로 개발한다.

- 지역을 추가할 때마다 실제 플레이와 기존 지역의 회귀 검증을 진행한다.
- 추가 도구, 물고기, 특수어, 보스, 증강과 직업은 플레이에 필요한 만큼 도입한다.
- 모든 미래 시스템을 사전에 설계하거나 밸런싱하지 않는다. 콘텐츠와 시스템의 범위는 제작 경험과 플레이 결과에 따라 조정한다.

**다음 단계 판단:** 전체 지역 제작이 진행되고 콘텐츠 추가가 기존 Run 흐름을 깨뜨리지 않는다. Meta 완성에 필요한 콘텐츠와 해금 대상이 충분히 구체화되어 있다.

## PHASE 6 — Full Meta Progression

**목표:** 데모의 저장/진행 기반을 전체 게임의 영구 성장으로 완성한다.

- 지역 해금, 도구 해금, Meta Currency, 영구 성장과 Hard Mode를 완성한다.
- Run 상태와 Meta 상태를 분리하고 새 Run의 초기화 및 같은 Run의 지역 이동을 함께 검증한다.
- 저장 데이터 버전 관리와 마이그레이션을 마련하고, 이전 버전 저장을 새 버전으로 옮기는 경로를 검증한다.

**다음 단계 판단:** 전체 게임의 해금/성장/저장 흐름이 연결되어 있고, 재실행과 버전 변경 이후에도 정해진 진행 규칙을 유지한다.

## PHASE 7 — Alpha

**목표:** 1.0에 필요한 핵심 시스템과 콘텐츠가 모두 존재하는 상태에서 전체 게임을 검증한다.

- 시작부터 최종 결과까지 완전한 Run을 반복 테스트한다.
- 지역 간 난이도, 빌드 성장, 경제와 주요 밸런스를 조정한다.
- 진행 단절, 빠진 콘텐츠와 핵심 시스템의 빈 부분을 해결한다.

**다음 단계 판단:** 필수 1.0 범위가 실제로 연결되어 플레이 가능하고, 주요 진행/콘텐츠 공백이 해결되어 안정화에 집중할 수 있다.

## PHASE 8 — Beta / Release Candidate

**목표:** 필수적인 경우를 제외하고 주요 신규 시스템을 추가하지 않으며 출시 안정성을 확보한다.

- 버그, 성능, 저장 안정성, UX와 접근성을 개선한다.
- 해상도/화면 옵션, 입력 동작, 오디오 믹싱과 빌드 안정성을 검증한다.
- 수정 후 관련 회귀 테스트를 수행하고 출시를 막는 문제를 우선 해결한다.

**다음 단계 판단:** 출시 후보 빌드의 주요 결함과 저장/진행 위험이 해결되었고 최종 배포 검증을 진행할 수 있다.

## PHASE 9 — Commercial 1.0 Release

**목표:** 상용 배포할 최종 빌드와 출시 자료를 준비한다.

- 실제 배포할 프로덕션 빌드를 만들고 해당 빌드를 기준으로 최종 회귀 테스트를 수행한다.
- 스토어 이미지·소개·영상 등 출시 에셋과 릴리스 체크리스트를 준비한다.
- 배포 빌드와 Git 버전을 식별할 수 있도록 기록하고 최종 확인된 빌드를 출시한다.

**완료 기준:** 1.0 빌드, 스토어 자료와 출시 체크리스트가 준비되어 최종 검증을 마친 버전이 배포되었다.

## PHASE 10 — Post-launch

**목표:** 실제 플레이 환경의 안정성을 우선 확보하고 이후 투자를 플레이어 데이터로 판단한다.

- 충돌, 저장 손상, 진행 불가 등 치명적인 문제를 먼저 핫픽스한다.
- 이후 실제 플레이어 피드백과 플레이 데이터를 바탕으로 밸런스 업데이트 및 추가 콘텐츠의 필요와 우선순위를 평가한다.
- 업데이트마다 관련 회귀 검증, 저장 호환성 확인, Git 이력과 NETBREAK_STATE.md 갱신을 유지한다.

추가 콘텐츠의 분량이나 출시 일정은 사전 약속으로 고정하지 않는다.
